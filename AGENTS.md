# AGENTS.md

Инструкции для агентов, работающих в этом репозитории (не для агентов, которые
пользуются готовым `rat` — этот протокол в конце).

## Состояние репозитория

- Готовы этапы **M0–M7**: схема и миграции, проекты, полный цикл задач (создание,
  статусы, правка, комментарии), поиск, лента событий, статистика, милстоуны,
  экспорт `md`/`jsonl`, автобекапы БД с ротацией, HTTP API, `rat serve`, web UI
  с записью (новая задача, статусы, милстоуны, комментарии), SSE, клавиатура,
  адаптив и UI-полировка.
- Милстоуны (PLAN §13) реализованы полностью: схема v3 (`milestones`,
  `issues.milestone_id`), `rat milestone add|ls|edit|close|reopen`, `--milestone`
  у `add`/`edit`/`ls`, `/api/milestones`, фильтр и панель в UI, блок в экспорте.
- `PLAN.md` — единственный источник требований: структура каталогов, схема БД, CLI,
  HTTP API, этапы M0–M7. Читать целиком перед крупной работой и не выдумывать
  файлы/команды/эндпоинты, которых там нет.
- Карта файлов и все команды с флагами — в `README.md` (разделы «Команды» и
  «Архитектура»). Меняете CLI — обновите `README.md` в том же коммите.
- Документация и сообщения — по-русски, идентификаторы кода — по-английски.

## Жёсткие ограничения (из PLAN §1, §11)

- Node **24**, ESM, расширение `.mjs`. В рантайме только `node:*`: `node:sqlite`,
  `node:http`, `node:test`. Никаких npm-зависимостей, better-sqlite3, express, jest.
- Никакой сборки в рантайме: Tailwind (M4+) компилируется standalone CLI в
  `web/app.css`, и результат **коммитится**.
- Удаления нет. Задача уходит в `cancelled`, комментарии неизменяемы (правка —
  новый комментарий).
- `src/core/store.mjs` — **единственный писатель в БД**. CLI и HTTP API
  вызывают его, а не SQL напрямую; `query.mjs`/`events.mjs`/`export.mjs` — только
  чтение; web UI пишет только через API.
- `events` — append-only. Каждое изменение (создание, статус, правка, комментарий)
  обязано оставить событие; историю задним числом не править.
- Не добавлять авторизацию, синхронизацию, уведомления, вложения, подзадачи,
  спринты, time-tracking, git-интеграцию, Electron/Tauri.

## Команды

CLI запускается из исходников, установки нет:

```bash
node bin/rat.mjs <command> ...        # на Windows шим: bin\rat.cmd
node --test "tests/**/*.test.mjs"     # все тесты (директория как аргумент не поддерживается)
node --test tests/m3-export.test.mjs  # один файл
node --test --test-name-pattern="idem" "tests/**/*.test.mjs"   # один тест
npm test                              # то же, что первая строка (package.json)
npm run build:css                     # пересобрать web/app.css
node bin/rat.mjs serve --port 4711    # web UI + API только на loopback
```

- `bin/rat.cmd` вызывает `node --no-warnings`: это подавляет `ExperimentalWarning` от
  `node:sqlite`. Не убирать флаг и не считать предупреждение ошибкой.
- База: `data/issues.db` (в `.gitignore`). Переопределение — `--db <path>` или `RAT_DB`.
  Для экспериментов и тестов всегда отдельная временная БД, не рабочая.
- Файлы `-wal`/`-shm` рядом с базой — норма (WAL), не удалять вручную.
- `exports/` — снапшоты; в этом репозитории каталог в `.gitignore`. Тесты и ручные
  проверки пишут только в песочницу (`--out <tmp>`), не в рабочий `exports/`.
- Сборки в рантайме нет. `tools/build-css.mjs` и `web/app.css` уже есть: Tailwind
  компилируется standalone CLI при разработке и результат коммитится. `rat serve`
  запускает только сервер, ничего не собирая.

## Инварианты данных и поведения

- Публичный id — `KEY-NUM` (`RAT-7`, `AXEL-3`); он же в CLI, API и URL. Внутренний
  `issues.id` наружу не отдавать.
- Номер задачи: `BEGIN IMMEDIATE` → `max(num)+1` по проекту → insert → commit.
  Не полагаться на автоинкремент и не делать `SELECT max` вне транзакции.
- Pragma на **каждом** коннекте: `journal_mode=WAL`, `busy_timeout=5000`,
  `synchronous=NORMAL`, `foreign_keys=ON`.
- Статусы: `open | doing | blocked | deferred | done | cancelled`. Приоритеты `0..3`, default `2`.
  Из `done`/`cancelled` выход только через `reopen`; `deferred` — открытый, уходить можно свободно;
  `doing` без assignee ставит actor.
- Определение проекта: `--project` → `$RAT_PROJECT` → самый длинный `root_path`,
  являющийся префиксом cwd → `meta.default_project`. Ничего не найдено — ошибка с
  подсказкой `rat project add`.
- `events.actor` заполняется всегда: `RAT_ACTOR` или `--actor`.
- Время — epoch ms. `labels` — нормализованный JSON-массив (lowercase, sorted).
- Милстоуны: `NULL` в `issues.milestone_id` — легальное состояние («без вехи»).
  Веха уникальна по `name_key` внутри проекта; `name_key` считается в JS
  (`trim+toLowerCase`), а не через `COLLATE NOCASE` (кириллица). Состояние только
  `open`/`closed`; закрытую веху нельзя назначать новым задачам
  (`ConflictError milestone_closed`). Прогресс — `done/(total−cancelled)`,
  `percent` округляется вниз, при нулевом знаменателе `0`. Привязка/отвязка —
  событие `edit {field:"milestone"}`, отдельного `events.kind` нет. Веха не
  удаляется, только `close`.
- Миграции применяет только `rat init` (PLAN §13). Команды на базе с чужой
  версией схемы не «догоняют» её сами, а падают `DbError` с кодом
  `schema_outdated` (exit 4) и подсказкой `rat init`; `doctor` показывает FAIL
  по схеме. Не добавлять запросы к новым таблицам без этой проверки — иначе
  старая база получит сырое «no such table».
- FTS5 (`issues_fts` + триггеры) с фолбэком на `LIKE`, если сборка без FTS5;
  проверка на старте.
- Exit codes: `0` ok, `1` не найдено, `2` ошибка использования, `3` конфликт перехода,
  `4` ошибка БД. `--json` — машиночитаемый вывод, `--quiet` — минимум.
- Автобекап (`src/core/backup.mjs`) — до команды, не чаще `RAT_BACKUP_INTERVAL`
  (24h), хранится `RAT_BACKUP_KEEP` копий (7), каталог `<каталог БД>/backups`.
  Копия — `VACUUM INTO` на отдельном коннекте. Сбой копии только предупреждает
  в stderr и не меняет код выхода; `--no-backup` / `RAT_BACKUP=off` отключают.
  Ротация бэкапов — не «удаление» из PLAN §1: задачи и события неизменяемы, а
  копии — внешние файлы.

## Контракты, которые нельзя ломать

- Схемы полей `--json` и ответов API считаются публичными: тесты их фиксируют,
  переименование полей — breaking change.
- `--body -` и `--title -` читают stdin (не экранировать кавычки в shell).
- `--idem <uuid>`: повтор с тем же id не создаёт дубль (проверка по `events.data.idem`).
- Экспорт: порядок полей jsonl фиксирован (задача — как в `rat ls --json`; событие —
  `id, issue, project, ts, actor, kind, data`), порядок записей — `project_key,num`
  для задач и `ts,id` для событий. `md` не зависит от текущего времени (только даты
  из данных, без блоков «сколько прошло»), поэтому оба формата побайтово
  воспроизводимы — это и проверяют тесты. Экспорт не пишет в БД.
- `/api/*`: только `127.0.0.1`/`localhost`/`::1`, без авторизации,
  `Cache-Control: no-store`, ошибки в форме
  `{"error":{"code":"...","message":"..."}}`. SSE `/api/stream` с
  `Last-Event-ID`. Милстоуны: `GET/POST /api/milestones`,
  `PATCH /api/milestones/:ref?project=K`; у задач поле `milestone` (имя или
  `null`), фильтр `milestone=none`.
- Один доменный слой `store.mjs` для CLI и API — валидация не должна расходиться.

## Web UI

- `rat serve` отдаёт `web/index.html` + статику + API. Только loopback.
- Экраны: сайдбар (проекты со счётчиками, мини-статистика, до трёх открытых
  милстоунов с прогрессом), список задач (фильтры, поиск, сортировка, фильтр по
  милстоуну внутри проекта, чипы вех), деталь задачи (включая назначение вехи),
  лента событий, модалка новой задачи (проект + милстоун).
- Клавиатура: `/` поиск, `n` новая задача, `j/k` навигация по списку, `Enter` открыть,
  `Esc` назад/закрыть, `c` комментарий, `s` статусы.
- SSE `/api/stream` обновляет список/деталь/счётчики; fallback — polling 5s.
- Любая мутация в UI и любое SSE-событие должны обновлять текущий экран,
  список проектов со счётчиками и мини-статистику (единый `refreshAll` с debounce).
- Устаревшие fetch-ответы не должны перетирать свежие: используется счётчик запросов
  и `AbortController` для in-flight list-запросов.
- Адаптив: ≥768px — сайдбар + строки; <768px — drawer с оверлеем + карточки.

## Протокол агента-пользователя (PLAN §7)

`rat` собран — работайте только через CLI или HTTP API, без прямого SQL.

- Цикл: `rat next [project] --json` → `rat claim ID` → работа → `rat comment ID "..."`
  с итогом (что сделано, файлы, коммит) → `rat done ID --reason "..."`.
- Дешёвое чтение: `rat show ID --json` (задача + последние события), `rat ls --json`,
  `rat log --since 1d --json`, `rat next --json`.
- Полный контекст проекта: `rat export --format jsonl --events --out -` (md — для
  человека и git-diff, jsonl — для загрузки в LLM).
- Автор события берётся из `--actor` или `RAT_ACTOR`; без него будет `cli`. Ставьте
  свой идентификатор, чтобы в `rat log` было видно, кто что сделал.
- Повторы безопасны: `add`/`comment` принимают `--idem <uuid>`, длинный текст —
  `--body -` (stdin).
- Коды выхода: `0` ok, `1` не найдено, `2` ошибка использования, `3` конфликт
  (недопустимый переход статуса), `4` ошибка БД/записи. В скриптах смотрите на код,
  а не на текст.
- Задачу нельзя удалить: закрывайте через `done`/`cancel`, ошибочный статус
  исправляйте `reopen`. Комментарии неизменяемы — уточнение пишите новым.
